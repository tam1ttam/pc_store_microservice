Rắc rối ở common-lib:

1. NHỮNG THỨ BẮT BUỘC (ngoài DTO):
- ResponseSuccess<T>, ResponseError, PageResponse<T>: wrapper cho API response
- BaseMapper<M, V>, EntityCreateUpdateMapper<M, V, R>: interface mapping Entity ↔ ViewModel
- AbstractAuditEntity: base entity với tracking thời gian (createdOn, lastModifiedOn) & người dùng (createdBy, lastModifiedBy)
- AuthenticationUtils: lấy User ID, JWT từ SecurityContext
- BaseSecurityConfig: cấu hình OAuth2 JWT, Security Filter Chain
- Exception handlers (ApiExceptionHandler, GlobalExceptionHandler): global error handling
- ApiConstant: HTTP status codes và constants
- OpenApiConfig: Swagger/OpenAPI configuration

2. NHỮNG TRÙNG LẬP TRONG CODEBASE:

2.1 - TRÙNG LẬP EXCEPTION PACKAGE:
- Có 2 package exception khác nhau: tam.common.exception (15 classes) vs tam.common.exceptions (6 classes)
- exception package: NotFoundException, BadRequestException, DuplicatedException, ForbiddenException, AccessDeniedException
- exceptions package: ResourceNotFoundException (trùng NotFoundException), InvalidParamException (trùng BadRequestException), ConflictException, UnauthenticatedException, InvalidFileTypeException
- Còn có cả Forbidden.java và ForbiddenException.java trong exception package (2 class gần như giống nhau)
- Service khác nhau dùng package khác nhau: user-service dùng exceptions package, khác đó ko import gì

2.2 - TRÙNG LẬP EXCEPTION HANDLER:
- ApiExceptionHandler trong exception package: dùng ErrorVm model, handle nhiều exception cụ thể
- GlobalExceptionHandler trong exceptions package: dùng ResponseError model, handle exception khác
- Spring chỉ load 1 trong 2 (RestControllerAdvice ưu tiên hơn ControllerAdvice), cái kia bị ignore
- Kết quả: một số exception không được handle đúng, error response inconsistent

2.3 - HAI LOẠI RESPONSE STRUCTURE KHÁC NHAU:
- ResponseSuccess<T>: {status, message, data}
- ResponseError: {timestamp, status, error, message, path}
- Không consistent, services sẽ nhầm lẫn cách dùng

2.4 - DATE UTILITY TRÙNG LẬP:
- Có cả DateUtils.java và DateTimeUtils.java nhưng chưa rõ phân biệt chức năng

2.5 - KAFKA PACKAGE CHƯA DÙNG:
- Chỉ có cdc package trong kafka, chưa rõ implementation chi tiết

3. CÁC LỖI GÂY CHÍ MẠNG:

3.1 - SPRING SECURITY CONFLICT:
- common-lib có class AccessDeniedException extends RuntimeException
- Nhưng Spring Security cũng có org.springframework.security.access.AccessDeniedException
- Dễ import nhầm → exceptions không được handle đúng, runtime error khó debug

3.2 - HAI EXCEPTION HANDLER ACTIVE CÙNG LÚC:
- @ControllerAdvice vs @RestControllerAdvice cùng trong common-lib
- Spring chỉ chọn một, cái kia bị ignore
- Một số exception không được catch hoặc response không consistent
- Lỗi lâm sàng: service A throw exception của exception package nhưng handler của exceptions package không biết xử lý

3.3 - AUTHENTICATION UTILS KHÔNG AN TOÀN:
- extractUserId() throw exception nếu không authenticated, nhưng không có try-catch guard
- Có thể bị lợi dụng để DoS nếu không handle catch properly

3.4 - KAFKA DEPENDENCY TRONG COMMON-LIB:
- spring-kafka được include trong pom.xml common-lib
- Nhưng chỉ notification service hoặc saga service thực sự cần
- Toàn bộ service khác phải load dependency này → phình JAR, overhead memory

3.5 - OAUTH2 AUTHORIZATION SERVER TRONG COMMON-LIB:
- spring-boot-starter-oauth2-authorization-server được include
- Chỉ identity-service cần, toàn bộ service khác cũng pull dependency
- Authorization server resources lạn qua các services

3.6 - SWAGGER AUTO-CONFIG CHO TẤT CẢ SERVICE:
- OpenApiConfig bean trong common-lib được auto-load cho mọi service
- Toàn bộ service đều có /swagger-ui.html
- Có thể bị leak API definitions nếu không configure properly

4. CHI TIẾT PACKAGES:

4.1 - PACKAGE: base/
- ResponseSuccess<T>: generic response wrapper với {status, message, data}
- ResponseError: builder pattern error wrapper với {timestamp, status, error, message, path}
- PageResponse<T>: pagination wrapper với items, page, totalPage, limit, totalItem; có static method fromPage() convert Page<E> to PageResponse<R>
- Đây là bắt buộc cho tất cả service, cần unify response structure

4.2 - PACKAGE: mapper/
- BaseMapper<M, V>: interface base với 3 method toModel(V), toVm(M), partialUpdate(@MappingTarget M, V)
- EntityCreateUpdateMapper<M, V, R>: extends BaseMapper, dành cho Create/Update operations
- Cả 2 là interface pure, dùng MapStruct annotation để implement
- Bắt buộc khi service cần convert Entity ↔ ViewModel

4.3 - PACKAGE: model/
- AbstractAuditEntity: base @MappedSuperclass với CreationTimestamp, UpdateTimestamp, CreatedBy, LastModifiedBy
- Dùng CustomAuditingEntityListener để populate createdBy, lastModifiedBy
- ResponseMessage: wrapper với {code, message, status, data} - TRÙNG LẬP với ResponseSuccess/ResponseError
- Bắt buộc extends cho entity của service có audit tracking

4.4 - PACKAGE: exception/ (15 classes)
- Exception classes: NotFoundException, BadRequestException, DuplicatedException, ForbiddenException, AccessDeniedException, CreateGuestUserException, InternalServerErrorException, MultipartFileContentException, SignInRequiredException, StockExistingException, UnsupportedMediaTypeException, WrongEmailFormatException, ResourceExistedException
- Custom exceptions: Forbidden, ForbiddenException (2 class gần như giống nhau, TRÙNG LẬP)
- Handler: ApiExceptionHandler (@ControllerAdvice), dùng ErrorVm model, handle NotFoundException, MethodArgumentNotValidException, BadRequestException, DuplicatedException, ConstraintViolationException, InternalServerErrorException...

4.5 - PACKAGE: exceptions/ (6 classes)
- Exception classes: ResourceNotFoundException, InvalidParamException, ConflictException, UnauthenticatedException, InvalidFileTypeException
- Handler: GlobalExceptionHandler (@RestControllerAdvice), dùng ResponseError model, handle ResourceNotFoundException, MethodArgumentNotValidException, ConflictException, MaxUploadSizeExceededException, InvalidParamException, InvalidFileTypeException, UnauthenticatedException, DisabledException...
- CONFLICT: cả 2 package handle cùng một loại exception như MethodArgumentNotValidException nhưng theo cách khác

4.6 - PACKAGE: viewmodel/error/
- ErrorVm: record với {statusCode, title, detail, fieldErrors}, dùng cho ApiExceptionHandler
- Khác với ResponseError của base package

4.7 - PACKAGE: security/
- BaseSecurityConfig: @Configuration, setup OAuth2 Resource Server với JWT
- Dùng jwtDecoder() với NimbusJwtDecoder + SecretKeySpec
- jwtAuthenticationConverter() để convert JWT claims to GrantedAuthorities
- SecurityFilterChain cho phép /api/auth/**, /v3/api-docs/**, /swagger-ui/**, /swagger-resources/**, /actuator/** mà không cần auth
- Bắt buộc cho tất cả service cần OAuth2 validation

4.8 - PACKAGE: utils/
- AuthenticationUtils: static methods extractUserId(), extractJwt() từ SecurityContext
- DateUtils: format/parse LocalDate với pattern "dd/MM/yyyy", format/parse LocalDateTime với pattern "HH:mm dd/MM/yyyy"
- DateTimeUtils: format LocalDateTime với pattern "dd-MM-yyyy_HH-mm-ss"
- MessagesUtils: lấy message từ MessageCode enum
- SortUtils: xây dựng Sort object từ query parameter
- TRÙNG LẬP: DateUtils vs DateTimeUtils (cùng mục đích, pattern khác)

4.9 - PACKAGE: config/
- CorsConfig: cấu hình CORS cho các service
- OpenApiConfig: Swagger bean với security scheme Bearer JWT
- ServiceUrlConfig: load service URLs từ properties (warehouse_url, stock_history_url...)
- Có thể conflict nếu service custom lại ServiceUrlConfig

4.10 - PACKAGE: constants/
- ApiConstant: HTTP status codes (CODE_200, CODE_400, CODE_401...) và HTTP status messages (OK, Bad request, Unauthorized...)
- MessageCode: business message codes (WAREHOUSE_NOT_FOUND, PRODUCT_NOT_FOUND, NAME_ALREADY_EXITED...)
- PageableConstant: pagination constants
- QueryConstants: query-related constants
- SortConstants: sort-related constants

4.11 - PACKAGE: customEnum/
- ValidEnum: annotation @interface để validate enum value
- EnumValidator: implement ConstraintValidator<ValidEnum, Enum>

4.12 - PACKAGE: specification/
- EntitySpecification: generic Specification builder
- SearchOperation: enum các operation (EQ, LIKE, GT, LT...)
- SearchQueryParser: parse search query to SpecSearchCriteria
- SpecSearchCriteria: criteria model
- SpecificationBuildQuery: build JPA Specification từ criteria

4.13 - PACKAGE: csv/
- anotation/ folder: chứa custom annotation cho CSV
- BaseCsv: base class cho CSV entity
- CsvExporter: export data to CSV file

4.14 - PACKAGE: kafka/cdc/
- BaseCdcConsumer<K, V>: abstract base class cho Change Data Capture consumer
- processMessage(V record, MessageHeaders headers, Consumer<V> consumer)
- processMessage(K key, V value, MessageHeaders headers, BiConsumer<K, V> consumer)
- config/: BaseKafkaListenerConfig
- message/: Operation.java, Product.java, ProductCdcMessage.java, ProductMsgKey.java (schema cho CDC messages)
- RetrySupportDql: retry logic cho DQL
